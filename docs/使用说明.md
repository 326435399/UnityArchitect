# Unity Architect 使用说明

> 本文档与软件内「帮助 → 使用说明」内容保持一致，功能更新时两处同步修改。
> 最近更新：2026-11-12 · 版本 v2.7.0

本工具是**纯扫描查看器**：所有节点、成员与关系都来自对 Unity 工程的扫描解析，没有新建 / 打开 / 保存工程、导入导出旧格式、撤销重做和手动编辑结构的功能，扫描即最新。核心用途：

1. 看脚本与脚本之间的关系（继承 / 组合 / 依赖 / 事件）；
2. 看脚本与场景之间的关系（脚本挂在哪些 GameObject 上）；
3. 看 ScriptableObject 资源实例与脚本之间的引用链。

## 一、快速上手

1. 双击打开 `Unity关系图工具V2.html`（建议 Chrome / Edge）。
2. 点工具栏 **扫描 Unity 工程**，选择 Unity 工程根目录（含 Assets 文件夹）。授权一次后，以后每次打开都会自动重新读取。
3. 也可以直接把工程根目录 / Assets 文件夹**拖进窗口**；没有目录权限时用菜单「文件 → 选择文件夹（兼容模式）」。
4. 点 **载入示例工程** 可以先看功能效果。
5. 扫描后，标题栏与「工程」页会显示当前 Unity 工程的名字与目录（桌面版显示完整路径；浏览器受安全限制只能拿到文件夹名），随时确认正在观察哪个工程。

## 二、扫描范围

每次扫描固定覆盖三类内容：

- **脚本**：.cs 文件的类型、成员（变量 / 事件 / 属性 / 方法）、脚本间依赖；
- **场景与预制体挂载**：脚本挂在哪些 GameObject 上（含场景内对象与预制体对象）；
- **SO 资源实例**：.asset 文件在其 m_Script 能对应到脚本类型时，解析成 SO 资源节点，与所属类连「SO 实例」关系，并按序列化字段名连出「字段 → 资源」引用线。

不扫描的内容：贴图、音频、材质、模型等其余资源一律不导入；AssemblyDefinition（.asmdef）只作为分层元数据读取，不生成节点；`ProjectSettings / Packages / Library` 等 Unity 自身目录永远不会导入。

- 左栏「筛选 → 层级（一键切换）」：**仅脚本 / 含挂载 / 全部**，扫描后即时切换画布显示层级，不重读文件。
- 已删除的脚本重新扫描后自动清除；布局位置在重新扫描时保留。

## 三、查找所有引用（Visual Studio 式）

在检查器里，每个成员旁都有引用按钮和**引用计数徽章**（像 VS 编辑器里的「N 个引用」）：

- **事件 ⚡**：点击后画布聚成三列——**定义**（谁声明了 event）→ **注册**（哪个类哪个方法 `+=` / `-=`）→ **激活**（哪个方法 `Invoke` 触发）。右侧同时列出每个引用的**类、方法与代码行**，例如：
  - `db.State.Changed += Refresh;` → 注册 · G1View.OnEnable
  - `Changed?.Invoke();` → 激活 · G1State.Fire
- **同名事件不串线**：追踪只针对你点击的那个类的事件——`G1State.Changed` 和 `TowerGameState.Changed` 即使同名也各自独立，互相不会混入对方的引用。
- **画布上的角色标识**：追踪时节点直接标注角色——**定义** 标在声明类的标题栏，**激活** 标在触发它的方法行旁，**注册 / 注销** 标在调用它的方法行旁（如 `Bind`）；同时会画出「注册 / 激活」指向定义类的彩色箭头，激活发生在其他类时同样补箭头。
- **变量 / 属性 ⇥**：**字段类型**（最左，该字段指向的对象）→ **声明**（含初始值）→ **写入**（哪里被赋值 / 修改）→ **读取**（哪里被使用）；即使引用都在同一个类里，也能看到它指向的类型对象。
- **容器字段按元素类型识别**：`TrackedRow[]`、`List<TrackedRow>`、`IReadOnlyList<TrackedRow>`、`Dictionary<string, TrackedRow>` 这类容器只是包装，字段类型一律解析为元素类型 `TrackedRow`（字典取值类型，嵌套泛型递归解包），并在类图里画出对应的聚合边。
- **嵌套类是独立节点**：类内部声明的 `class RowState` 会作为自己的节点参与关系图（全名 `外部类.嵌套类`），检查器里显示「嵌套于」哪个外部类；`List<RowState>` 这类字段会正确连到嵌套类上。`Outer.Inner` 形式的类型引用只算 `Inner` 本身，不会多连一条到 `Outer` 的假边。
- **方法 ⇥**：**定义** → **调用**；方法组引用（如 `+= Refresh`）也算一处引用。
- 工具栏的「事件追踪 / 数据流向」按钮对选中节点生效（多个成员会弹选择框）。
- **链式访问按类型准确归因**：`db.State.Count` 这类多级访问会沿 `db` 的声明类型 → `State` 的返回类型逐级解析，把引用归到真正声明该成员的类上；无法解析的写法退化为按成员名匹配。
- **多跳数据流**：解析器同时记录「方法参数存入字段」「调用实参」「跨对象赋值」。例如 SO 资源被 GameRoot 序列化引用，`GameRoot.Start` 里 `g1Controller.Bind(db)` 传入参数、`Bind` 内 `this.db = database` 存入字段——可在数据流向里追出「SO 资源 → GameRoot.db → G1Controller.db」整条链。
- 所有追踪视图都是临时视图，不写入工程文件；再点一次（或 Esc）退出并精确还原布局。

## 四、Assembly 分层视图

工具栏 **Assembly 分层**：读取工程里的 .asmdef，把脚本按程序集**自上而下**分层——

- **主链在左侧一列、全部左对齐**：没有人引用它的入口程序集（如 Boot）在最上层，它引用的层排在下一行，依赖方向始终朝下，例如 `Boot → GamePlay / UI（平级同一行）→ Data → Core`；所有层带的左边缘对齐在同一条竖线上；
- 同 depth 的程序集是**平级关系**，共享同一行左右并排；
- 引用关系同时支持两种写法：asmdef 里直接写**程序集名**，或勾选 **Use GUIDs** 后写其他 .asmdef 资源的 GUID（通过旁边的 .meta 文件解析回程序集名）；
- 每层是一条横向层带，**层名标注在层带左侧的彩色标签里**，层带底色与边框常显，边界一目了然；
- **非主链分组全部放右侧栏**（彼此左对齐、在主链高度内纵向等分分布）：SO 资源（`.asset` 生成的 ScriptableObject 实例）、预制体（prefab）、GameObject 层（未纳入 asmdef 的场景 / GameObject；混有无 asmdef 脚本类时叫「（未分组）」）、Editor 程序集；
- SO 资源实例卡片右上角有 **`SO.asset`** 徽章，与 SO 脚本定义类明显区分；
- 再点一次退出并还原布局。

注意：.asmdef 只作为**分层元数据**读取，不生成图节点。

## 五、画布与检查器

- **聚焦依赖**：选中节点 → 工具栏「聚焦依赖」（或右键菜单 / 快捷键 **G**）。左侧一列「谁引用我」、右侧一列「我依赖谁」，再点一次（或 Esc）退出并还原布局；聚焦模式下右键菜单的该项会变成「取消聚焦依赖」。聚焦时，引用了聚焦类型的**成员行右侧会显示关系徽章**（聚合 / 组合 / 依赖 / 序列化 / 继承等），一眼就能看出是哪个字段、哪个方法引用了它——比如追踪 `TrackedRow` 时，`rows` 行会标出「聚合」。
- **右键菜单与快捷键**：右键节点即选中；菜单含「定位到（**F**）」「聚焦依赖 / 取消聚焦（**G**）」「数据流向（**T**）」；右键到具体成员行时，数据流向 / 方法追踪 / 事件追踪会直接对准该成员（如右键 `rows` 行 →「数据流向 · rows」）。**F** 没有选中节点时退化为适应画布。
- **成员高亮按钮**：工具栏有 **事件 / 协程 / UnityEvent / 委托** 四个开关，点亮的类别其成员文字换成对应醒目颜色并加粗（事件粉、协程橙、UnityEvent 青、委托黄），在大卡片里一眼定位复杂成员；再点一次恢复默认文字色。四个开关可任意组合叠加。
- **模式发光提示与互斥**：聚焦依赖 / 事件追踪 / 数据流向 / Assembly 分层 / 孤立选中 属于**画布模式**，同一时间只会有一个生效——切入新模式时旧模式自动退出还原，当前模式的工具栏按钮**持续发光**；再点一次（或 Esc）退出后停止。
- 工具栏还有 **全部显示 / 全部隐藏 / 孤立选中** 三个批量按钮：「孤立选中」只显示选中节点及其直接引用（**只统计脚本类**，GameObject / 预制体 / 场景不参与孤立判定），再点一次退出并还原显示。
- 左栏顶部输入框：位于左栏最上方，在「资源 / 筛选」页是**资源筛选**，切到「检索」页就变成**全库检索**（节点、成员、类型与关系），Ctrl+K 也会自动聚焦到这里。
- 滚轮缩放、空白处拖动平移、节点拖拽移动、框选多选、双击定位。
- Ctrl+K 全局检索、Ctrl+A 全选、F 适应画布、Esc 退出当前模式。
- 布局：**分层** / **网格** / **Assembly 分层** 三种。
- 检查器成员面板按 **变量 / 事件 / 属性 / 方法** 四组排布，与画布节点卡片分组一致；每个成员显示引用计数。
- 节点卡片上的名称、类型、成员均来自扫描结果，只读展示。
- 默认黑色主题，右上「主题」可切换明暗；小地图可在「筛选 → 显示」里关闭。

## 六、导出

- **导出 Markdown**：按 变量 / 事件 / 属性 / 方法 分组；事件列出**注册 / 注销方**与**触发方**；方法列出**被谁调用**；变量列出**写入 / 读取方**；另含**程序集依赖**、GameObject / 预制体的**挂载脚本清单**与**挂载对象清单**。
- **导出 PNG**：当前画布截图（浏览器模式下按二进制写出，可直接打开）。

## 七、GameObject / 预制体组件组成

- 每个场景 / 预制体对象（GameObject）的卡片上都有「**组件**」分组，按 YAML 文档顺序列出全部组件：内置组件（Transform、Rigidbody、BoxCollider、Animator…）与自定义脚本；每行最左侧是**类型图标**——移动轴（Transform）、碰撞盒（Collider）、相机、灯光、声音、动画、UI 层叠等矢量小图形，一眼识别组件种类；自定义脚本统一显示蓝色 **C#** 页面图标（可点击跳到脚本节点），未启用的组件图标半透明； 组件名一律显示**真实脚本名**：工程内脚本按 GUID 解析到脚本节点；官方包脚本（EventSystem、StandaloneInputModule 等）通过补充读取 `Library/PackageCache` 里的 `.cs.meta` 解析出真实名字，不再显示一排 MonoBehaviour；
- 预制体文件的根对象以「**预制体**」类型出现（带 prefabRoot 标签），场景中的 `PrefabInstance` 会生成一条「**组合 · 预制体实例**」边，从宿主对象指向预制体对象；
- 序列化字段引用（`字段名: {fileID: …}` 指向同一场景/预制体内的其他对象）会生成**带字段名的引用边**，可直接看出对象之间谁引用谁；
- 组件超过 8 个时显示「▼ 还有 N 个组件（点击展开）」，点击展开 / 收起；
- 检查器里有「**组件组成**」卡片：编号、类型、内置组件 / 脚本标识、未启用标记。

## 八、常见问题

- **扫描后没有反应 / 失败**：确认选的是工程根目录（里面有 Assets 文件夹）；或改用拖入 / 兼容模式。
- **官方包组件都显示 MonoBehaviour**：扫描时浏览器有读取预算，选**工程根目录**（含 Library）才能补读 `PackageCache` 的 `.cs.meta` 解析出 EventSystem / InputSystemUIInputModule 等真实名字；只选 Assets 目录会预算耗尽导致组件名解析失败。
- **事件追踪 / 数据流向为空**：需要**重新扫描一次**生成方法体引用记录。
- **Assembly 分层提示没有 asmdef**：工程里没有 .asmdef 文件（或扫描时未包含），无法按程序集分层。
- **SO 资源没有出现在图里**：只有 m_Script 能对应到工程内脚本类型的 .asset 文件才会生成节点；外部包内资源的 GUID 不会解析。
- **预览面板（内嵌 iframe）里目录授权被拦**：用「拖入文件夹」或「兼容模式」。
- **浏览器不能后台静默读盘**：系统安全限制，本工具用「一次授权 + 自动重扫 / 拖放」做到最接近自动。
- **同名事件 / 同名方法 / 同名字段**：只按**接收者类型**归因——接收者链解析不了（反射、委托、局部变量等）的引用一律不计入，不会把工具类里的 `set.Contains(...)` 误算成别的类的同名方法，也不会污染引用视图。反射 / 委托间接触发无法追踪；数据流向对「方法返回值再赋值」「委托回调」等间接路径也无法覆盖。
